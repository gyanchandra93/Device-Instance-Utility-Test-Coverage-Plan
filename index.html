1. Decision on each feedback item

This section lists each Device Instance Utility behaviour, one row per behaviour. The first-column codes group those behaviours by area of the page: 0 entry and Techscape eligibility, 1 Project Materials, 2 Group Templates, 3 Group Instances, 4 Live Preview, 5 Create All and footer.

Each row gives that behaviour a mark — [covered], [proposed], [newly proposed], or [not required] — and names the E2E or unit in sections 2–4. It also says whether that check is its own journey or is folded into another test. Use this table only as a crosswalk. The lists to implement from are sections 2–4.

Business purpose A PPM project imports its Oracle material, turns that material into parent and child devices, and can refresh the import without losing the material. The device list is the proof that devices were saved.

Coverage type Happy path

5. Shared notes

  • Group ID entry no longer uses the PostHog flag enable-groupid-features. Eligibility comes from the project's executing CTC. isProjectTechscapeEnabled in e2e/utils/techscape-eligibility.ts reads isTechscapeEnabled from GetProjectDetails. E2E uses CTC 0101 when Techscape must be enabled and CTC 0102 when it must be disabled. Do not call FFConfigs.enableGroupIdFeatures or wait for PostHog. A program device list hides Add Group without that check.
  • The utility page is a desktop tool. e2e/AGENTS.md (Local Operating Context, lines 66–71) says Device Instance Utility journeys use the default Desktop Chrome viewport and are not meant for mobile. The mobile view is not yet ready, so new E2E should run once per behaviour, not as a desktop-plus-mobile matrix.
  • Some current visual specs still loop VISUAL_VIEWPORTS. That is existing coverage. Do not copy that matrix for the proposed or newly proposed journeys. And also remove the mobile view coverage.
  • Combine related actions in one journey when they share setup: non-PPM add/edit/delete; template copy/search/delete; override cancel then confirm on the same materials spec.
  • Do not treat a success toast as proof that devices were saved. Create All journeys finish on /projects/:id/devices unless the case is expected to create nothing.
  • The Oracle budget WireMock stubs are used by Import Materials and Refresh Materials in e2e/tests/projects/utility-ppm-create-all.spec.ts (PPS-3). The project number is an isolated E2E-RUN-… value, and the stub returns one camera, E2E Camera Alpha. The PPM versus non-PPM button spec also creates a PPM project with isolatedOracleProject(), but it does not click Import or Refresh, so it does not call those stubs.
