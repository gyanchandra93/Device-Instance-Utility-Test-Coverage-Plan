1. Decision on each feedback item

This section lists each Device Instance Utility behaviour, one row per behaviour. The first-column codes group those behaviours by area of the page: 0 entry and feature flag, 1 Project Materials, 2 Group Templates, 3 Group Instances, 4 Live Preview, 5 Create All and footer.

Each row gives that behaviour a mark — [covered], [proposed], [newly proposed], or [not required] — and names the E2E or unit in sections 2–4. It also says whether that check is its own journey or is folded into another test. Use this table only as a crosswalk. The lists to implement from are sections 2–4.

5 Complete / incomplete / cancel / rejected Create All [proposed] PPS-3, 5, 6, 7 Keep as separate E2E journeys. They have different outcomes.

explanation:

These are four proposed E2E journeys, not one test and not a unit.

  • Create parent and child devices, then find them on the device list (PPS-3): valid Create All. Expected devices are on the device list; the count-0 template creates none.
  • Incomplete configuration cannot create devices (PPS-5): required fields missing. Create All stays disabled and the device list gains nothing.
  • Cancelling Create All creates nothing (PPS-6): dialog is cancelled. Group Instances and Live Preview stay; the device list gains nothing.
  • Rejected Create All leaves the project unchanged (PPS-7): API refuses the batch (for example a duplicate device name). The error stays in the dialog and the device list does not gain those names.

They stay separate because success, blocked submit, cancel, and API rejection are different outcomes. Do not merge them into one spec.
